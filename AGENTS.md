# AGENTS.md


## Project Overview

This repository is an Astro-based static personal website and Markdown blog. It is intended to be hosted from GitHub and deployed automatically through Cloudflare Pages, with the custom domain managed through Alibaba Cloud DNS / Cloudflare DNS configuration.

Current stack:

- Astro 7 static site generation.
- Markdown content collections for blog posts.
- Plain CSS in `public/styles.css`.
- Static output generated to `dist/`.

Important paths:

- `src/pages/index.astro` - homepage.
- `src/pages/blog/index.astro` - blog listing page.
- `src/pages/blog/[...slug].astro` - blog post detail route.
- `src/content/blog/` - Markdown blog posts.
- `src/content.config.ts` - blog content schema and loader.
- `src/layouts/BaseLayout.astro` - shared page shell.
- `public/` - static files copied directly to the final site.
- `dist/` - generated build output; do not edit by hand.

## Blog Content

Add Markdown posts under `src/content/blog/zh/` for Chinese posts and `src/content/blog/en/` for English translations.

After adding or editing a post, `npm run build` regenerates its Open Graph share image automatically through `prebuild`. To regenerate share images alone, run `npm run og:images`.

Recommended frontmatter:

```markdown
---
title: "文章标题"
description: "文章摘要，用于列表页、SEO 和 RSS。"
pubDate: 2024-01-15
updatedDate: 2024-01-20
tags: ["Astro", "AI", "开发"]
lang: "zh"
translationKey: "article-slug"
---
```

Required fields:

- `title`
- `pubDate`

Optional fields:

- `description`
- `updatedDate`
- `tags`
- `draft`
- `category`
- `lang` - `zh` or `en`; defaults to `zh`.
- `translationKey` - stable key for matching translations; usually the slug.

Draft posts with `draft: true` are excluded from the blog list, detail pages, and RSS feed.

Post URLs are generated from file paths:

- `src/content/blog/zh/hello-astro.md` -> `/blog/hello-astro/`
- `src/content/blog/zh/my-post/index.md` -> `/blog/my-post/`
- `src/content/blog/en/my-post.md` -> `/en/blog/my-post/`

## Markdown Migration Workflow

For Yuque-exported Markdown or similar exported articles, use the project-local importer instead of copying files by hand:

```bash
npm run import:yuque -- \
  --file "/path/to/article.md" \
  --title "文章标题" \
  --slug "article-slug" \
  --description "文章摘要" \
  --tags "标签1,标签2"
```

Concrete example:

```bash
npm run import:yuque -- \
  --file "/Users/coderman/Downloads/KVPlat平台介绍.md" \
  --title "KVPlat 平台介绍" \
  --slug "kvplat-platform-intro" \
  --description "介绍基于元数据配置的业务 KV 配置平台，包括多租户、多级缓存、配置变更审核和主要模块设计。" \
  --tags "KVPlat,低代码,Spring Boot,Vue,多租户"
```

Then run:

```bash
npm run build
```

Detailed workflow: `docs/blog-migration.md`.

## Blog Translation Workflow

Generate English Markdown drafts from existing Chinese posts with:

```bash
npm run translate:blog
```

Translate a single post:

```bash
npm run translate:blog -- --slug kvplat-platform-intro
```

The translator reads `src/content/blog/zh/` and writes `src/content/blog/en/`. Existing English files are skipped unless `--force` is passed. Always manually review AI-generated translations and run `npm run build` before publishing. Detailed workflow: `docs/blog-translation.md`.

The importer copies the Markdown into `src/content/blog/<lang>/`, downloads remote images into `public/images/blog/<slug>/`, rewrites image links to local paths, removes Yuque OCR HTML comments, and adds Astro frontmatter.

## Markdown Images

For the simplest and most stable setup, put blog images in `public/images/blog/` and reference them with absolute site paths:

```markdown
![图片说明](/images/blog/demo.png)
```

Avoid local machine paths such as:

```markdown
![bad](/Users/name/Desktop/demo.png)
![bad](C:\Users\name\Desktop\demo.png)
```

Image file recommendations:

- Use lowercase English names.
- Prefer hyphens over spaces.
- Keep file extensions and Markdown references exactly the same case.
- Prefer local copies for important images instead of remote hotlinks.

If migrating from Obsidian or Typora, convert non-standard image syntax such as `![[demo.png]]` to standard Markdown image syntax.

## Personal Website Layout Guidance

A practical personal developer site should keep the first screen direct and useful:

1. Hero / intro
   - Name or handle.
   - One-line identity.
   - Primary links: blog, GitHub, email, resume, projects.

2. About
   - Short professional summary.
   - Technical direction and current focus.

3. Skills / stack
   - Group languages, frameworks, infrastructure, and tools by category.

4. Projects
   - 3-6 selected projects with description, tech stack, links, and screenshots.

5. Blog / notes
   - Technical articles, project writeups, and learning notes.

6. Contact
   - Email, GitHub, LinkedIn, X/Twitter, WeChat QR code, or other preferred channels.

## SEO and Sharing Basics

All SEO tags are emitted by `src/layouts/BaseLayout.astro`, so every page inherits them. Current coverage:

- Meaningful `<title>` and `<meta name="description">`.
- Canonical URL built from `site` in `astro.config.mjs` plus the page path.
- `hreflang` alternates linking the Chinese and English versions, with `x-default` pointing at Chinese.
- Open Graph tags: `og:type`, `og:site_name`, `og:title`, `og:description`, `og:url`, `og:image`, `og:locale`.
- Article pages add `article:published_time` and `article:modified_time`.
- Twitter card tags using `summary_large_image`.
- `<meta name="author">` set to `CODERMAN`.

Open Graph images are per post: `scripts/generate-og-images.mjs` renders a 1200x630 PNG from each post title, category, and language into `public/images/og/<lang>-<slug>.png`. Article pages pass that path to `BaseLayout` as `ogImage`.

Production domain: `https://coderman.me`. Keep `site` in `astro.config.mjs` and `Sitemap` in `public/robots.txt` aligned with this domain.

## Cloudflare Deployment

The site deploys as a Cloudflare Worker with static assets. `wrangler.toml` declares the `[assets]` block that points at `./dist`:

```toml
name = "coderman-site"
compatibility_date = "2026-10-30"

[assets]
directory = "./dist"
```

Requirements:

- Build command must actually build the site, for example `npm ci && npm run build`. A no-op command such as `exit 0` leaves `dist/` empty and the deploy fails.
- Do not add `binding` to `[assets]`. Wrangler rejects it in an assets-only Worker.
- No Cloudflare adapter is needed. The site is static, so `@astrojs/cloudflare` is not installed and must not be pulled in by build settings.
- Build output directory: `dist`
- Root directory: repository root
- Production branch: `main`

DNS/domain notes:

- Keep one canonical domain, such as `example.com` or `www.example.com`.
- Redirect the non-canonical domain to the canonical domain.
- Use HTTPS-only mode.
- Be careful when mixing Alibaba Cloud DNS and Cloudflare DNS; normally one provider should be authoritative for a domain or delegated subdomain.

## Editing Rules for Agents

- Keep the Astro static deployment model intact.
- Do not edit `dist/` directly.
- Do not commit `node_modules/`.
- Prefer semantic HTML and plain CSS before adding client-side JavaScript.
- Keep shared styling in `public/styles.css` unless a component-specific style is clearly better.
- Do not store secrets, API keys, DNS tokens, or Cloudflare credentials in this repository.
- When adding assets, use clear names such as `public/images/blog/cloudflare-dns-flow.png`.
- Use `npm run import:yuque` for Yuque-exported Markdown migrations.
- Run `npm run build` after changing routes, layouts, content schema, RSS, imported Markdown, or Markdown examples.
- Do not hand-edit `public/images/og/`; regenerate with `npm run og:images` or let `prebuild` handle it.
- Verify visual changes in a browser when possible.

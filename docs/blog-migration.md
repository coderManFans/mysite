# Blog Migration Workflow

This project uses Astro content collections for Markdown blog posts. Use this workflow when migrating Markdown exported from Yuque or similar platforms.

## Quick Command

Use this template for any Yuque-exported Markdown file:

```bash
npm run import:yuque -- \
  --file "/path/to/article.md" \
  --title "文章标题" \
  --slug "article-slug" \
  --description "文章摘要" \
  --tags "标签1,标签2" \
  --category "vibe-coding-projects"
```

Real example already used for the KVPlat article:

```bash
npm run import:yuque -- \
  --file "/Users/coderman/Downloads/KVPlat平台介绍.md" \
  --title "KVPlat 平台介绍" \
  --slug "kvplat-platform-intro" \
  --description "介绍基于元数据配置的业务 KV 配置平台，包括多租户、多级缓存、配置变更审核和主要模块设计。" \
  --tags "KVPlat,低代码,Spring Boot,Vue,多租户"
```

Then verify:

```bash
npm run build
```

## What the Script Does

`scripts/import-yuque-md.mjs` performs these steps:

- Reads the source Markdown file.
- Removes existing frontmatter.
- Removes HTML comments generated by Yuque OCR export.
- Converts Obsidian-style image syntax like `![[demo.png]]` to Markdown image syntax.
- Downloads remote Markdown and HTML image URLs.
- Stores images in `public/images/blog/<slug>/`.
- Rewrites image links to `/images/blog/<slug>/image-N.ext`.
- Adds default image alt text when missing.
- Writes the final post to `src/content/blog/<slug>.md`.
- Adds Astro-compatible frontmatter.

## Arguments

Required:

- `--file` - absolute or relative path to the Markdown file.

Recommended:

- `--title` - article title shown in the blog list and article page.
- `--slug` - URL slug. Example: `kvplat-platform-intro` becomes `/blog/kvplat-platform-intro/`.
- `--description` - article summary for SEO, RSS, and the blog list.
- `--tags` - comma-separated tag list.
- `--category` - category slug: `distributed-microservices`, `ddd-domain-modeling`, or `vibe-coding-projects`.

Optional:

- `--date` - publication date in `YYYY-MM-DD` format. Defaults to today's date.
- `--force` - overwrite an existing post with the same slug.

## Manual Review Checklist

After importing, review the generated Markdown file:

- Confirm the title, description, date, and tags.
- Replace default image alt text with meaningful descriptions for important images.
- Check whether section headings should be promoted or renamed.
- Remove platform-specific text that should not be published.
- Confirm code blocks have language identifiers when possible.
- Run `npm run build`.
- Open `/blog/<slug>/` locally and check image layout.

## Commit Pattern

Use a focused commit per imported article:

```bash
git add src/content/blog/<slug>.md public/images/blog/<slug>
git commit -m "Add <title> blog post"
git push
```
